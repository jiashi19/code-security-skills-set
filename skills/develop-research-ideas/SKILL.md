# 科研 Idea 推进与查新

## 核心立场

- 将“明确的新增贡献和进一步探索空间”作为判断重点，不追求“绝对原创”或“从未有人做过”的完美 idea。
- 将相似工作视为定位和推进研究的起点。已有方法在相关问题上的尝试，不等于这个方向失去了价值，不因标题、术语或框架相似就过度防御性地否定。
- 默认优先尝试保留和发展用户提供的 idea。寻找能够推进、完善或深化已有思想的实质差异：解决未解决的不足，揭示新的机制或边界，或以新的问题组织方式产生可验证的新认识。
- 让叙事服务于真实贡献。允许更完整、更有说服力的故事，但不把改名、措辞变化或未经验证的收益当作创新。
- 保持可证伪性。若充分调研后，核心问题、关键方法和主要贡献存在不可绕过的高度重合，且无法形成实质性区分，停止为当前版本的创新性辩护；明确指出撞车工作、重合之处及现有差异不足的原因。

## 选择工作模式

- **想 idea**：根据用户目标、已知工作和约束提出或发展候选方向，优先形成可验证的新增贡献。对有希望的候选执行下述查新流程；未完成查新的候选只称为待验证方向。
- **检查 idea**：先忠实复述用户的想法，再系统检索、深读近邻工作、比较贡献边界，最后给出创新性论证或具体撞车结论。
- 用户同时要求两者时，先检查当前版本，再发展有证据支持的修改版本。不要把修改后的贡献倒算为原始 idea 已经具备的创新。

## 工作流程

### 1. 界定想法与约束

用一小段话概括目标问题、研究对象、输入信息、核心机制、预期输出、验证方式及拟新增贡献。区分用户已明确的设计与待验证假设；不要擅自补入关键机制来制造差异。

优先使用当前对话已有约束，例如时间、算力、数据与代码可用性、评测范围。只有缺失信息会改变研究判断时才提问；其余先给出可修正的假设并继续。

### 2. 系统检索近邻工作

- 将问题拆成检索轴：目标问题、技术机制、使用的信息或监督信号、应用与评测场景。组合关键词、同义词及领域术语，避免只搜索用户的命名。
- 检索一批最接近的论文，同时考虑经典工作和近期进展；优先按接近程度选取，不以会议等级、引用数或发表时间代替相关性判断。
- 从最接近工作追踪参考文献、后续引用、作者项目页、相关代码及后续版本；合并同一工作的预印本与正式发表版本，标明所读版本。
- 记录检索日期、主要检索式与覆盖范围。以新增检索是否仍改变近邻集合或贡献判断来决定是否继续，不为了凑固定篇数机械扩展。
- 优先依据论文全文、附录和作者官方代码。综述、博客或搜索摘要可以帮助发现线索，但不能单独支撑“已做过”或“没有做过”的结论。
- 无法检索或获取关键全文时，继续完成可做的分析并明确证据缺口；将结论标为暂定，不声称完成系统查新或确认创新。

### 3. 深读最接近工作的核心部分

对足以影响判断的每篇工作，阅读方法、关键算法或公式、实验和局限；必要时查看附录与代码。不要仅凭标题、摘要或表面相似性猜测方法。

提取并核对：

1. **问题设定**：究竟解决什么，适用于什么假设和场景。
2. **信息来源**：输入、监督信号、历史信息、训练与测试可见内容。
3. **核心机制**：关键步骤如何运作，技术细节如何支撑其贡献。
4. **评测证据**：比较对象、数据、指标、消融和结果能够支持什么，不能支持什么。
5. **贡献边界**：作者明确主张了什么，全文实际覆盖了什么，哪些是你的推断或尚待核实。

给关键比较提供可定位的依据：论文链接与章节、页码、公式、算法或官方代码路径。将“未在已读材料中找到”与“作者明确不支持”分开表述；不能用摘要未提及来证明全文没有实现。

### 4. 比较实质差异并发展方向

围绕真正影响判断的维度建立对照表，至少比较问题设定、核心机制、信息来源和主要贡献；不要用功能清单堆出差异。对每项差异回答：

- 我们具体新增、改变或推进了什么？
- 最接近工作为何不能直接完成这件事，或其结论为何不能直接覆盖？
- 这一差异为何有意义，预期解决哪个具体不足？
- 什么实验、反例或分析能证明它的独立价值？

区分概念相似、实现复用与核心贡献重合。允许基于现有组件做有价值的改进；不要要求每个模块都新。也不要自动将“增加 agent”“更换模型或数据集”“组合 A+B”“换个应用场景”视为足够创新：只有它们产生新的能力、机制认识或可靠实证贡献时才论证其价值。

在否定前，实际尝试寻找可成立的强化版本，例如改进关键机制、补足遗漏假设、扩展有意义的边界、解释失败原因或建立新的实证结论。不要通过任意缩窄题目或重新命名来规避真正的重合。

### 5. 给出证据约束下的判断

按当前证据选择一种结论：

- **存在可信贡献空间**：指出保留的核心、实质增量、最近邻工作和仍需验证的假设。
- **值得发展但尚未证实**：指出最有希望的差异、缺失证据和下一步验证；不要把候选贡献写成已证实的创新。
- **当前版本严重撞车**：列出具体工作，逐项解释核心问题、关键方法和主要贡献的重合，以及剩余差异为何不足。停止当前创新性论证；若存在有根据的转向，单独提出并标明需要重新查新。

不要因为尚未发现相同论文就宣称“首次”；也不要因为研究包含相似模块就判定不可做。将创新性、技术可行性和潜在发表价值分开判断，不承诺录用。

## 输出要求

根据任务规模调整篇幅，但保留以下内容：

1. **当前判断与 idea 定义**：先明确当前版本值得怎样推进，以及判断的证据范围。
2. **最接近工作与实质比较**：提供可核验来源、阅读范围及对照表，区分事实与推断。
3. **一段创新性论证**：仅在证据允许时写成连贯段落，说明“已有工作做到哪里 → 尚存什么具体不足 → 我们新增什么 → 为什么有意义 → 如何验证”。使用“拟、预期、待验证”等准确措辞，不虚构实验结果。
4. **最小验证方案**：优先设计能区分我们与最接近方法的实验、反例、消融或低成本试验；借助已有实现降低成本，并说明什么结果会推翻贡献主张。
5. **未解决问题**：仅列会实质改变判断的证据缺口和风险，不堆泛化的防御性免责声明。

如当前版本严重撞车，用具体重合分析替代创新性段落；不要为了满足输出格式继续强行论证。若关键全文缺失，则只能给出有条件的贡献假设与补证路径。
